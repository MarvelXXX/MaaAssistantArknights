# ArkPilot

用中文对话分析明日方舟画面，或让模型逐步通过 ADB 操作游戏。每一轮都会读取新的游戏截图，在指令台展示判断理由和执行结果。

## 开始使用

1. 在 Windows 上安装 Node.js 22 或更新版本。打开模拟器或连接已授权 USB 调试的安卓设备，将明日方舟切到前台。
2. 双击同目录的 **start.cmd**。首次启动会安装 npm 依赖并打开 [本机指令台](http://127.0.0.1:17321)。也可以在此目录运行以下命令。

   ~~~sh
   npm ci
   npm start
   ~~~

3. 在设备画面上方选中要操作的 ADB 设备。确认预览对应目标账号。MuMu 有时会为同一实例列出两个 ADB 连接。
4. 打开 **连接设置**，填写 Model URL 和 API Key。接口使用 OpenAI 兼容的 Chat Completions 格式。URL 可以是服务根地址、带路径的 API 前缀或完整的 chat/completions 地址。根地址自动补 v1，本地免鉴权服务可留空 Key。
5. 点击 **获取模型** 或直接填写服务端模型 ID。仅列出一个模型的服务也可在发送时自动识别。有视觉能力的模型选 **截图 + OCR 与模板匹配结果**，纯文本模型选 **仅 OCR 与模板匹配结果**。
6. 在对话框输入指令，回车发送，Shift + Enter 换行。**只读分析**适合查看局面，**允许操作**支持点击、滑动、返回和等待。

可直接尝试这些指令。

- “分析当前画面，告诉我可以进行哪些操作。”
- “打开任务界面，领取可以领取的日常奖励。”
- “这个结算界面显示的是几星？你看到了哪些掉落？”

运行中可以点击 **停止**。已发送到设备的操作可能已经生效。助手提问时，直接在同一设备的对话中补充即可。默认每条指令最多执行 24 步，可在设置中改为 1 至 100 步。

## Maa 自动化与战斗攻略

打开指令台的 **攻略与 Maa**。Windows x64 上的 Maa 完整发行包提供原生任务引擎。程序会检测下载目录中解压的 MAA 文件夹，也可以在启动前用环境变量指定同时包含 MaaCore.dll 和 resource 的目录。[Maa 官方发行包](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases)

~~~powershell
$env:ARK_MAA_HOME = 'D:\MAA'
npm start
~~~

- **日常与代理** 可直接领取日常与周常任务奖励，或指定关卡、次数运行代理指挥。代理要求账号已解锁该关的代理指挥。程序将理智药和源石补充次数设为零。
- **领取活动合成玉** 会检查幸运墙和限时开采，在活动开放且当日次数可用时领取免费合成玉。也可在允许操作模式下发送 `/活动合成玉`，由本机 Maa 直接执行。实际到账数量以游戏奖励画面和首页余额为准。
- **战斗作业** 支持按关卡搜索 PRTS、输入单份作业码或导入本地 JSON。打开作业后可查看编队、部署格、朝向、开技和等待条件。可先点 **用 Maa 检查兼容性**，这一步只校验内核能否加载作业。执行时请先进入对应关卡准备页，检查普通或突袭难度及当前编队。勾选自动编队会调整当前队伍。原生任务可直接运行，无需模型 Key。[PRTS 作业站](https://prts.plus/)
- **视频攻略** 可从关联视频链接查看来源，也可输入 BV 号或完整 B 站链接（含分 P）读取公开标题和简介。简介里的单份作业码可继续导入。填写关卡后，点 **只查引用此 BV 的作业** 可筛出该关热门作业中明确引用这段视频的方案。切到视频攻略，点 **读取关联 B 站视频画面** 可预览、解读或识别平台提供的公开单段 MP4；受限或不兼容的播放源可换用本地录像。
- 对本地单场录像，**完整录像转作业** 调用 Maa 的实验性 VideoRecognition，尝试识别编队、关卡和战斗操作。成功后可预览并导出 JSON。完整的游戏原声或无声录像都可尝试，关键是画面需包含编队、关卡及战斗过程。剪辑、遮挡、无法解码或缺少关键画面都可能导致失败。生成的草稿需核对时机与位置。[Maa 集成协议](https://docs.maa.plus/zh-cn/protocol/integration.html)
- 对剪辑攻略，选取起止秒数后点 **解读所选片段**。浏览器最多抽取 12 个带时间的画面并发送给配置的视觉模型，返回的参考笔记可编辑后附给对话。此模式只分析画面，不转录语音，对短暂技能动作可缩短采样区间。也可直接粘贴文字攻略。作业和笔记保留在当前页面，需长期保留作业时可导出。

部分 Windows Maa 运行包无法直接解码 MP4。ArkPilot 会尝试调用 FFmpeg 转为临时 MJPEG 录像，再交给 Maa 识别。可将 ffmpeg 加入 PATH，或在本工具目录的本地 .env 文件中用 ARK_FFMPEG 指定其完整路径。转码与识别使用独立临时目录，完成或取消后清理。

### 用自己的干员抄作业

悖论模拟使用 Maa 的悖论作业任务。可从干员列表左端发送“导入银灰悖论作业 96845，自动找到银灰并完成模拟”，由 Maa 导航并选择作业指定的技能。如果已经进入该关的技能准备页，请手动选好技能，再点 **执行此作业**。悖论的其他参战干员由关卡提供。

使用已导入的悖论作业时，可从国服首页或全干员列表左端发送 `/悖论作业`，让 Maa 定位干员并按附件选技能。若作战结束后出现剧情，可发送 `/跳过剧情`，由 Maa 识别跳过按钮并确认。在行动结束画面核对掉落后，发送 `/退出结算` 返回关卡页。这些网页指令均可在模型离线时使用。

Maa 作战期间，设备预览会继续更新。如果任务链在教学对话中断，指令台会重新观察现场。已有对应作业时，可以要求“跳过教学对话，按已附作业逐个部署”。在 16:9 画面下，ArkPilot 根据 Maa 的关卡地图计算拖卡时的实际落点，确认选向界面出现后再完成朝向。

打开 **攻略与 Maa → 我的干员**，给账号的名册起名。**读取 Maa 已保存的名册** 会读取当前 Maa 安装目录下的 `data/OperBoxData.json`。也可以导入文件，或在游戏干员列表清除筛选后点击 **用 Maa 扫描当前账号**。名册保存在当前浏览器。切换游戏账号时应选择对应名册。选择名册后，聊天分析会向所配置的模型提供干员资料。

扫描可能漏识别。只有手动标记未持有，或自行核对并勾选完整名册，ArkPilot 才会把缺少记录的干员判为未持有。可以在面板修正等级、补填技能资料或只录入常用干员。例如：

~~~json
{"operators":[{"name":"克洛丝","elite":1,"level":55,"skill_level":7},{"name":"能天使","owned":false}]}
~~~

`elite` 取 0–2，`skill_level` 为公共技能等级 1–7。按技能分别记录专精可填 `skill_levels`，例如 `[7,7,10]` 表示三技能专三。多职业同名干员可用 Maa 的干员 ID 指定形态。

导入作业后点击 **按我的干员适配部署**，或在聊天里要求适配。模型参考作业、账号练度、关卡地形、基础射程和已查到的攻略，优先采用作者提供的备选。通过校验后，面板会展示更新后的编队、技能、部署格、朝向和时机，Maa 执行当前这份作业。可导出或恢复原作业。资料不足、关键召唤物缺失或新部署格不适用时，可以补全资料或换作业；战斗结果以实际结算为准。

### 在对话中查找和分析视频

选择 **仅查攻略（无需设备）** 后，可以关闭模拟器。例如发送“联网找 1-7 的低配作业和视频，分析开局 10 到 40 秒，按我的干员改编队，先给我看部署步骤”。指令台会列出实际访问的来源。助手可以搜索网页摘要、阅读 PRTS Wiki 正文、查询作业站和相关 B 站视频，视频平台限制公开搜索时仍可从作业作者给出的 BV 找到视频。

聊天中的视频分析使用 FFmpeg 从公开 B 站单段 MP4（最多 180 MiB）抽取 8 个带时间的画面，交给所配置的视觉模型。可指定 BV、分 P 和起止时间，省略时间时会在整个分 P 抽样。短暂的开技或撤退可指定更短片段重看。文字模型可查询资料和分析名册，画面解读需要视觉模型。

在对话中也可发送“找一份 1-7 的作业，列出干员和开技条件”“使用 Maa 代理 1-7 三次”或“执行已附上的作业”。模型可以搜索、导入和说明攻略。选择原生任务后，由 Maa 连续执行并回报事件，结束后助手重新观察游戏画面。**只读分析** 允许查阅攻略并禁止游戏输入。Maa 报告任务链结束时，是否三星以实际结算为准。

## 图像识别与执行

ArkPilot 是独立的本地程序。它参考 Maa 按画面识别结果选择下一步的设计，从工作区的 Maa 资源目录读取部分模板、阈值及感兴趣区域，通过 OpenCV 匹配任务领奖、邮件、编队开始和结算星级等标志。识别结果带有来源、位置及当帧目标 ID。上游可据此核对资源定义。[Maa 仓库](https://github.com/MaaAssistantArknights/MaaAssistantArknights) · [任务协议](https://docs.maa.plus/zh-cn/protocol/task-schema.html)

Windows OCR 提供屏幕文字与位置。视觉模型还可以直接判断图标和场景。模型结合当前指令、近期对话与已执行步骤，一次返回一个结构化动作。程序将目标 ID 或相对坐标转换为实际设备像素，通过 ADB 输入。输入前会复查前台游戏、画面尺寸与像素变化，输入后重新观察。模型可回答、询问、报告完成或说明为何无法继续。动态场景中的识别质量和响应速度取决于所接模型。

| 能力 | 适用条件 |
| --- | --- |
| Maa 模板 | 默认读取仓库根目录 `resource/` 中选定的国服模板，接近 16∶9 的画面会缩放到 1280×720 进行匹配 |
| Windows OCR | 使用系统已安装的 OCR 语言包，优先选择客户端对应语言。识别状态显示在“识别结果”中 |
| 纯文本模型 | 根据文字和模板目标 ID 点击，也可返回或等待。纯图标和拖动操作需要切换到视觉模型 |
| 游戏客户端 | 支持前台运行的国服官服、B 服、繁中服、日服、韩服和国际服；外服使用 OCR 和模型视觉 |

服务只监听本机回环地址。设备预览与 Maa 录像识别在本机完成。发送指令时，指令、近期对话、附带攻略和所选识别输入会提交到指定模型服务。解读视频片段会提交所选时间段的抽样画面。获取模型列表也会使用填写的 Key。Key 仅在运行内存中使用，刷新页面后需重新填写。非密钥设置保存在当前浏览器。

## 设备与资源路径

程序自动查找 Android SDK、MuMu 的标准安装路径和 PATH 中的 adb。网络模拟器可在连接设置的设备选项中输入 ADB 地址，例如 127.0.0.1:16384，再点击 **连接**。设备离线或未授权时，先检查模拟器的 ADB 开关或安卓设备上的调试授权提示。

可在启动前通过 PowerShell 指定路径和服务端口。

~~~powershell
$env:ARK_ADB = 'D:\Android\platform-tools\adb.exe'
$env:ARK_MAA_RESOURCE = 'D:\MaaAssistantArknights\resource'
$env:ARK_PORT = '17321'
npm start
~~~

若将 ArkPilot 移出仓库，可用 `ARK_MAA_RESOURCE` 指向已有的 Maa 资源目录。找不到模板资源时，程序会显示状态并继续使用可用的识别来源。

## 验证

在此目录运行 `npm test`。测试使用本地模型协议替身和内存设备，覆盖指令到点击再到重新观察、追问、文本输入、坐标映射、只读限制、拒绝过期画面、步数上限与停止任务。

## 批量首通

在进程环境变量或 ArkPilot 目录的 `.env` 中设置 `ARK_REWARD_QUEUE`，指向本机账号的 JSON 清单。在允许操作、截图与 OCR 模式下发送 `/首通清单`。保持网页、服务和模拟器运行。点击停止会取消当前任务，再次发送同一指令时会先核对实机余额和中断关卡。清单旁的 `.run/首通进度.md` 会随每项结算更新。

需要关闭或刷新网页时，可改用 `/后台首通清单`。本地服务和模拟器保持运行即可。重新打开指令台会接回同一队列，显示当前进度和画面，也可以点击停止。运行中的模型凭据只在内存中使用。电脑或服务重启后，在网页中重新配置凭据并发送该指令即可从已保存进度恢复。

清单包含 `account`（账号标识）、`serial`（所选设备）和按优先级排列的 `targets`。可填写 `uid` 与首页显示的游戏 ID 比对。每项包含唯一 `id`、`chapter`、`label`、给模型的游戏路线 `route`、奖励种类 `currency`（`prime` 或 `orundum`）、正整数 `amount`、理智消耗 `ap` 和前置 ID 数组 `requires`。`stage` 用来限定作业关卡，`crystal: true` 标记需要事相结晶的章节。邮件或任务等金额不定的免费奖励可标记 `claimAvailable: true`。首通需要关卡结果与首页余额增量相符，无法对应时会保留待复核。游戏截图按当前网页配置发送至所选模型，进度文件保存在本机。

已核对的关卡可以填写 `guideId`（作业号）或 `plan`（完整作业）。教学关使用系统预设阵容时可设 `fixedTeam: true`。需要模型按画面部署时可设 `useNative: false`。修改同一账号的清单后，新路线和优先级会在当前关卡结算后生效。

可在 `retryGuideIds` 中按优先顺序填写同关的备选作业号。实战未通过时，进度会记下用过的作业，重试会选下一份。对于已经多次失败、正在等待复核的关卡，补充新的备选作业后可以继续重试。已经核实到账的关卡和余额异常的关卡会保留原记录。

更正失败关卡的打法后，可提高该项目的整数 `revision` 以立即重试。固定阵容的教学关支持 `resumeAfterStep`。它表示视觉操作完成的最后一个部署步骤（从 1 起算）。之后 Maa 用当前战场接续剩余作业，可在干员卡解锁时及时部署。
